# Focused shell same-node diagnostic

The exact old 4.10 core 2eaec7d and candidate 7f7e487 were built clean with the same GCC 13.3 native Make defaults and runtime libraries, on the retained shell node. The old executable reproduces the historical accepted e7cb28d binary byte-for-byte. Current frozen suite definitions, invocation, fixture preparation, output and filesystem oracles and C supervisor were reused unchanged. CPU 0; adjacent old/new pairs; rotated case order; ten measured rounds plus two warmups per case/version; five old-first and five new-first measured pairs. All 72 observations pass correctness. Independent audit recomputes every distribution.

Function calls: 22.086→48.519 ms, +26.432 ms (+119.68%). String transform: 60.516→69.788 ms, +9.272 ms (+15.32%). Both have disjoint observed ranges and all ten candidate pairs slower. This confirms two focused regressions; it does not establish a universal shell slowdown. Traversal: 1042.490→1051.289 ms, +8.799 ms (+0.84%), overlapping ranges, five candidate pairs slower. Treat traversal as near-equal/noise-scale in this experiment; its historical cross-host improvement is not a causal candidate gain.

Four separate post-timing strace/perf invocations pass correctness. Calls have identical 72 syscall totals and six reported errors in each version, suggesting no syscall amplification in this case. Software CPU profiles contain 23 old and 46 new samples, zero lost. Sample counts are small; full profiles are retained as leads, not proof of a causal change. The separate scripting diagnostic already has richer allocation evidence for calls. No core modification, accepted raw replacement, Labs update or release recommendation was made.

Present preference remains Nift for bounded Nift-owned mixed/programmatic workflows, and established shells where compatibility or their interactive model matters. Agent-friendly explicit contracts remain valuable; confirmed call/string costs still warrant investigation. Mature-Nift preference assumes these paths are reliable and fast, rather than treating programmability as permission to ignore regressions.
