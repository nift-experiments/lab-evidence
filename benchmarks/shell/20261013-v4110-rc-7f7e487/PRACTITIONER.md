# Practitioner draft

For everyday interactive use I would choose Bash/Zsh where compatibility and their established tooling matter, or Fish/Nu when their particular interactive/data model is desired. For Nift-owned programmable automation and mixed website/helper tasks, Nift is compelling: one programmable runtime and explicit contracts can make an agent-maintained project easier to inspect and verify. This does not make it the universal shell or an automatic replacement for existing scripts.

The complete expanded matrix includes filesystem, processes, pipelines and algorithms, with correctness and implementation boundaries preserved. Native Nift filesystem APIs and external-tool shell implementations are both useful but answer different implementation questions. Startup is not throughput; no global average is claimed.

Most historical Nift medians improve or vary slightly; function-call latency rises 22.586→46.722 ms (+106.86%) across different shared hosts. This needs matched-node confirmation before version attribution. Agent-friendly explicitness is an authoring advantage, not an excuse for a confirmed execution regression. Retain useful ownership/order/invalidation semantics and improve concrete slow paths.
